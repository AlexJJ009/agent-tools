## 两处真实的局部偏差

**1. 验收导航没有真正降低认知负荷。** 它把“这是合成材料”的标签写出来了，却没有先告诉你场景是什么、输入材料是什么、现在要评价什么。用户需要自己跨多个链接拼出关系。这与“正文先讲清楚，索引只提供进一步核查”的要求有差距。已按三个场景重写 [Human Review](reviews/human-review.md)，把原请求、来源角色与评价任务直接放在正文。

**2. 练习规则继承了过强的“必须重建”倾向。** 原 prompt 的 “Good checks force reconstruction” 与固定列出的重建/迁移题型没有覆盖轻量比较和表达判断。PRD 并没有要求全用填空，但仅保留旧 prompt 容易让一种示范变成默认套路。已根据新反馈改为按学习目标和用户明确的精力偏好选题型：可以填空、比较几个表述、选择并说明理由、诊断、排序、局部改写或独立写作。选择正确不等于能独立写出段落，帮助程度仍要区分。

这两项是可局部修正的问题，不需要推翻现有模块或重做一轮大型研发。

## 实际部署还缺什么

只读检查发现：逻辑路径 `~/projects/obsidian-vault/read_papers` 实际落在 `/mnt/c/AppsExternal/Obsidian/vault-repo/personal_knowledge_base/read_papers`；其 `.claude` 链接到 `~/projects/.claude`，`.codex/skills` 也指向同一共享技能目录。项目适配器并非安装测试里假设的独立项目目录。

旧安装器要求同时安装 `.claude`，所以这里会被目录边界检查拒绝。用户随后明确授权增量拆分项目入口，并要求先支持 Codex。v0.2 改为只管理 Codex 的 `.agents` 与 `.codex`：不再安装/删除 Claude 别名，不移动共享源目录。挂载项目仅作为明确选中的 WSL Codex 项目写入，不修改 Win11 用户 profile。

这是**实现对环境的假设尚未满足**，不是 PRD 换版，也不是用户缺少反馈。[路径读取证据](/home/alex_mercer/projects/_artifacts/agent-tools/codex-learning-workflow-migration/feedback-20260927/installation-topology.json)保存了实际解析结果。初次预检查没有运行安装器。后续定向验证又发现：只新增 `.agents` 会与旧 `.codex/skills` 桥产生两个 `read-paper` 入口。因此安装器按精确旧源拆分项目桥，只给其他旧技能保留逐项链接，读论文走独立 `.agents`；清单记录原链接及浅层条目，回退遇到后来新增内容会停止而非覆盖。这部分已在当前 WSL Codex 激活；实际范围与观察见 [IMPLEMENTATION](IMPLEMENTATION.md)，不是原生 Win11 Codex 的部署证明。

## Agent 加入了什么；哪些不能成为日常负担

| Agent 选择的方案 | 服务的目标 | 应保持的边界 |
|---|---|---|
| route schema、revision、固定记录路径 | 阶段切换可恢复，记录可被脚本检查 | 用户不必手填这些表；不能把短答或普通解释强制变成重型流程 |
| 30 个固定用例、关键负例三次、6 条 holdout | 检查这次迁移的实际触发与边界 | 这些数字不是用户偏好或可靠性定理；不能为每次小改重复整轮成本 |
| AC-21 的两个代表场景用户体验 | 检查材料可读性、帮助程度与直接写稿用途 | 它是 Agent 当时写进并随 PRD 获授权的验收方法，不是实施末尾新增门槛；现在已有具体反馈，不应重复索要，也不能扩大成 proposal 技术审批或学习考试 |
| 合成方法卡、文献卡、结果包 | 固定可核查的输入，暴露参数和论证边界错误 | 适合回归/E2E 测试，不代表真实论文难度、用户掌握或所有任务可靠性；真实使用直接读取已有材料 |
| 临时 Zotero profile/library | 测试真实资料适配，又不修改日常库 | 不属于安装后的产品需求。先前使用 WSL 临时实例是现场平台假设需要纠正，已按要求清理；日常是一套 Win11 Zotero/library |

本次旧方案确实付出了较大评测成本：历史运行、修复与复核合计 138 个记录运行。成本在[验收结果](ACCEPTANCE.md)中公开；它不能成为以后每条 query、每次 prompt 微调的默认成本。本次只检查改动涉及的说明、练习策略与包装，不重跑旧整套 campaign。

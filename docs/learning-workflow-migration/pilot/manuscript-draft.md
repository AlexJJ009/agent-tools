# Fixture Draft — Not for Submission as Empirical Results

This document is based entirely on synthetic, evaluator-supplied observations. The cases described below were not executed as part of this writing task, and the draft does not claim real-world validation, statistical generalization, or priority over prior work. No citations are included because the supplied materials contain no real bibliography.

## Introduction

Computational experiments are governed by agreements that connect a research question to the configuration ultimately consumed by a model, generator, or scorer. Those agreements often contain details that appear operational but can change the meaning of a comparison: how many candidates are generated, whether a token limit applies to the response alone or to the combined prompt and response, and which representations a scorer treats as equivalent. A pipeline may nevertheless run to completion when any of these details is implemented incorrectly. Successful execution therefore establishes that a program ran, but not that it ran under the conditions required to support the intended inference.

This distinction is especially important when several mechanisms change together. In the supplied synthetic source cards, increasing the number of candidates from one to four coincides with a larger aggregate maximum output budget, so an accuracy difference of 40% versus 44% cannot be attributed specifically to candidate diversity. A second fixture holds the stated candidate count and per-answer token cap fixed and reports 42% versus 43%, but changes both the generation procedure and indicators of candidate quality; with only one run per condition, it likewise does not isolate diversity or quantify uncertainty. In both comparisons, configured token ceilings specify permitted use, not the number of tokens actually generated; equal per-answer caps therefore do not establish equal realized token use. A third fixture shows that normalizing leading zeros changes 5 of 50 answer-pair judgments, demonstrating that scoring rules can alter reported outcomes even when generated answers are unchanged. Together, these examples motivate a narrower prerequisite for trustworthy comparison: before interpreting performance, researchers should verify that the components which consume experimental settings and outputs implement the agreement actually under study.

We examine consumer-side readback as a lightweight way to perform this verification. Rather than checking only the declared configuration or the process exit status, a checker compares a supplied experimental agreement with the final values observed at the point of use. This design targets a specific class of setup error: a requested value may be syntactically valid and allow the program to complete, yet acquire a different meaning through defaults, aggregation, or scoring logic before it reaches the consumer. Reading the consumed value makes that semantic discrepancy visible. The checker is not intended to evaluate model quality, prove the validity of an experimental hypothesis, or replace tests of the underlying algorithm; it verifies whether selected conditions were instantiated as agreed.

The accompanying fixture evaluates this mechanism in three local, CPU-only cases, each containing one deliberately injected mismatch. The first requires four candidates per generator but exposes a consumed value of one. The second requires an 8,192-token response cap but applies 8,192 tokens to the prompt and response combined. The third requires integer-answer normalization but rejects `"007"` when the reference is `"7"`. Under the stipulated fixture outcomes, consumer-side readback identifies all three mismatches, whereas a comparator based only on successful program exit identifies none because every program exits successfully. These results support a bounded claim: for the three constructed cases, inspecting final consumed values distinguishes agreement violations that execution status alone cannot detect.

This study should therefore be read as a mechanism demonstration, not as evidence of downstream learning gains or operational reliability. The fixture includes no GPU training, production deployment, accuracy study of the checker, estimate of researcher time saved, or repeated sampling from a broader population of errors. It also does not establish that consumer-side readback is novel. A substantive evaluation must test the approach against a larger and independently assembled error set, record both false negatives and false positives, and determine when an observed mismatch materially changes a scientific conclusion. Within these limits, the present demonstration identifies a concrete verification target and a baseline that is too weak for it: an experiment can execute successfully while violating the conditions its result is meant to represent.

## Alternative Proposal Direction: Budget-Constrained Audit of Resource-Allocation Policies

An alternative project could shift from demonstrating setup-error detection to comparing resource-allocation policies under a fixed configured inference ceiling. The primary estimand would be the average effect on answer accuracy of assigning the ceiling to one candidate versus dividing the same ceiling across four candidates, with the model, generator procedure, scoring rules, and evaluation questions held fixed. This contrast jointly changes candidate count and the configured per-candidate cap: if the total ceiling is \(B\), the policies permit one candidate of up to \(B\) tokens or four candidates of up to \(B/4\) tokens each. It therefore estimates the effect of the allocation policy, not an isolated effect of candidate count or diversity. Whether any policy effect is mediated by useful answer diversity would remain an unverified causal claim.

The study would use a preregistered 2 × 2 design crossing allocation policy (one candidate with ceiling \(B\) versus four candidates with ceilings \(B/4\)) with generator procedure (baseline versus diversity-oriented). The base model, prompt template, question set, candidate selector, and integer-normalization rule would remain fixed. Multiple seeded runs would be used so that uncertainty is estimated across runs rather than inferred from a single comparison. Consumer-side readback would verify the configured total ceiling, candidate count, per-candidate caps, and scoring rule. Separately, runtime measurements would record the realized output tokens for every candidate, total realized output tokens per question, termination reason or truncation at the cap, and the number of valid candidates produced. Equal configured ceilings would thus remain a design constraint rather than being treated as evidence of equal realized output-token use.

A modest pilot could remain CPU-only and use a fixed set of questions with, for example, five preregistered seeds per cell; its purpose would be to estimate variance and determine whether a larger evaluation is warranted, not to establish a universal effect. The primary analysis would compare the two assigned allocation policies under their common configured total ceiling and would report realized token use rather than assume it was matched. Accuracy would be accompanied by candidate-level correctness, selection-oracle accuracy, the rate of distinct normalized answers, pairwise answer-similarity measures, and the fraction of decisions changed by normalization. Reporting these quantities alongside realized per-candidate and per-question token counts would diagnose whether policy effects coincide with candidate coverage, output length, truncation, answer variation, or selection performance. The interaction with generator procedure would estimate whether the effect of the allocation policy differs between the two procedures; it would not, by itself, identify diversity as the causal mechanism.

A preregistered superiority claim for the four-candidate allocation would be falsified if it failed to improve accuracy beyond the specified minimum effect under the common configured ceiling. Any apparent gain would need to be interpreted together with measured realized token use and scoring sensitivity: a ceiling does not guarantee equal consumption, and conditioning on realized usage alone does not isolate why the assigned policies differ. Evidence that answer diversity mediates a policy effect would require an additional identification strategy—for example, an intervention that changes diversity while preserving resource allocation and other determinants of candidate quality, or a prespecified causal mediation analysis whose assumptions are independently justified. Correlations among diversity diagnostics, candidate coverage, and accuracy would remain descriptive rather than causal. This design directly addresses the resource and measurement confounds in the supplied source cards while keeping both the proposed outcome and any diversity-mediated explanation separate from the fixture results already available.

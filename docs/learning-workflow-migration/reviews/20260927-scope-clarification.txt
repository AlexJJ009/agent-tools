对这一条需求，其实我应该解释一下：并不是说所有的开发全部都一下子定好目标之后，就直接放手去执行。

这里的 hands-off 是相对于教学和写论文这种场景来说的，针对不同的分支情况会有所不同。在实际做开发的时候，我们仍然会有自己相关的开发 skill 套件去约束它。但在本质上流程是一样的，都要定好需求、产出 MVP 等等。

我们并不是说开发时定一个粗略的目标就可以放手，而是把东西细化之后，开始不断进行大量迭代。在每一次小的实现过程中 hands-off 是没问题的；在需要探索性的任务上，给出足够大的动作空间去探索，这个 hands-off 也没问题。

所以用这个术语似乎容易引起一些歧义，希望现在的实践不会造成这么大的误解。

另外，安装预检查发现了一个此前没覆盖的环境问题：ReadPapers 实际位于 Windows 挂载目录，它的 `.claude` 又指向多个项目共享的目录。

关于这个问题，ReadPapers 一方面可能依赖 .claude 文件夹，另一方面也可能依赖 .agents 文件夹，这两个文件夹它可能都依赖。最早是因为这两种情况目前完全不支持，所以没办法。

但其实用户现在主要是在用 CodeX，很少或者最近基本都没有用 Claude。所以像 .claude 这种指向多个项目共享目录的情况，安装方案肯定不能这么用。也就是说，我们肯定得做增量式更新，把它更新到服务器上对应的 .codex 文件夹、.agents 文件夹或者 .claude 文件夹里面去

所以就意味着，现在的 ReadPapers 如果把所有东西全放在 .claude 里面，大家都去引用它的话，可能结构不太好，我们也允许它稍微重构一下，把这些区分开。

其实本质上，.claude 以及 .agents 文件夹里面干的事情是一样的，都是那一批 skill、hook 这些。

我们可以优先先把 CodeX 场景实现好，等之后确定要用 Claude Code 的时候，再把 .claude 支持上，现在可以先不用支持 .claude

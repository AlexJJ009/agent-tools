# 2026-09-27 用户反馈与处理

来源：[本轮用户原文](20260927-user-feedback.txt)。这是对已提交样例的实际反馈，不能再写成“尚未收到用户反馈”。原样例未改写，仍按 [provenance](../pilot/provenance.json) 的摘要值定位。

| 评价对象 | 用户的具体判断 | 能记录的结论 | 未被评价或证明的内容 |
|---|---|---|---|
| Method 完整示范 | 拆解彻底、清晰；理由充分，细致程度可以接受 | 本例的可读性、解释与帮助程度通过 | 问题较简单，不证明复杂论文也能同等处理 |
| 练习反馈 | 看过来源与原请求后，认为反馈准确、有用 | 本例的反馈方式达标；下一步按场景提供多种题型 | 未发生真实用户作答、修订、迁移，不能记成能力提升 |
| Manuscript 与备选 proposal | 稿件达标；学术、问题导向，论证边界有自觉；形式可通过 | 表达与论证边界的评价通过 | 用户明确没有细看 proposal 技术内容；可行性、新颖性与设计未获确认 |
| Human Review 导航 | 初看不知道要做什么，也不知道材料的作用 | 这是实际可读性缺陷，需要修改入口 | 原先的独立审阅通过不能抹去这次用户反馈 |
| 合成评测 | 适合开发与验收，但不能过度依赖 | 保留为固定输入的回归/E2E 工具 | 不将合成成功外推成真实研究能力或全部场景可靠性 |

## 本轮改动

- [Human Review](human-review.md) 按三个场景直接给出材料背景、原始请求、产物入口、用户要判断的内容和已收到的结论。无需先读 JSON 才能知道任务。
- [练习指令](../../../skills/retrieval-practice/SKILL.md) 与[题型说明](../../../skills/retrieval-practice/references/practice-design.md) 支持 cloze completion、contrastive examples、discriminative judgment、局部诊断/改写和 free production；按目标及用户明确的精力偏好选择，不强制题型配额或疲劳问卷。
- [PRD 核查](../PRD-REVIEW.md) 区分用户目标、Agent 的工程选择与实际局部问题。初次审查保留 v0.1；随后的 R02/Codex 澄清已明确形成 v0.2，旧原文仍可通过 Git 对照。

AC-21 已得到具体、限定范围的用户评价。导航修订与题型规则的处理结果单独登记；不要求重新评价已经认可的三份样例。也不把收到反馈自动写成机器 gate、真实实验或论文方案批准。

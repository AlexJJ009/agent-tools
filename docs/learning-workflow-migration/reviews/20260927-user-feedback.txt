它非常彻底、也很清晰地把 method 的设计拆开来讲，给了一个例子和执行的 pipeline，以及最后在什么情况下会导出这个结果，并且对每一步都做出了解释。所以在清晰度上做得很好，对 method 本身的解释和理解也很不错。

但是，单看这个 method，我确实不知道它的核心材料是什么。所以我又进一步展开看了合成的测试材料，这才知道因为这是一个例子，属于 proposed 的场景，里面给出了 problem and motivation

然后我就有点一下子没有反应过来，说这个 method source 它的作用是什么？

method source 是一篇论文吗？就假设它是论文的 problem motivation，然后是它的定义这些东西吗？为什么我们会需要 method source 这个东西呢？

至少从形式上看，这个 learning example，其实我不知道什么样的形式是特别好的。但目前看，看懂是很容易的；不过看懂容易，也意味着这个问题可能本身就比较简单。

目前它的拆解力度还是很细的，我觉得这是一个优点，而且理由说得也很充分。这种细的力度我可以接受，算是过关的。

对于第二份材料，也就是 human review 这一部分的“练习与反馈片段”：

针对这个场景来说，human review 也是要产出给用户看的材料。我看“练习与反馈片段”这部分时，由于不懂这个学习场景是什么，一下子没法立即理解它，这里的学习者句子由评测者来编写，只用来检查一点的反馈方式。

用户稍微深入看了一下，就会发现其实是有一份合成材料。

然后第二项练习有一个写稿件的环节。它写了一个 introduction 出来，还有一个 alternative proposal，这个应该就是服务于选题的吧？

所以我觉得，对于我们已有的几个合成材料来说，它是达标的吧。

就这个 manuscript draft 而言，它其实是达标的。它这里的写作风格真的很学术，而且也挺问题导向的。

然後這裡 suggest 的這個 proposal directions 我觉得他的表述和写作规范都挺好的，但其实细节内容我并没有看，形式上是可以通过的。

问题意识是合格的，论证边界也有自觉。挺好的。

回到之前我们阐述的那个 exercise，我觉得它的种类可以丰富一点。

如果是练习写作，它可以用填空题，或者甚至可以做成给三个表述、让我们选哪个更好的形式。这就涉及到一个价值判断，和填空题不一样：填空题的话我们都要给答案，对吧？所以好像没关系。

所以这种 exercise 的形式是可以丰富一些的，全是填空题不行，全是选择题也不行，我觉得可以根据不同场景去切换。甚至用户觉得比较累的时候，可以让它给三个示例，让用户选哪个反映的主题最好这样子。

我觉得单纯用合成材料来做 evaluation（或者说做校验）的方式其实挺好的。这些材料目前看都还不错，至少我看到的三个材料都还不错。

这种方式的定位是：

1. 我们在开发的时候去依赖它们。
2. 它们是用来通过验收的，算是一个测试，或者说是偏 End-to-End 的一些测试。

我觉得这个做法非常的好，但是我们也不能依赖太多。

我现在还有一个突然忘了的问题，就是我们现在是照着哪一份 PRD 文件去实现的？它的版本是否是对的？

然后会有一个直接的质疑：这个 PRD 里，有什么是那种“偏移、漂移的需求”（就是它不是我们用户真的想要的需求）？有这样的东西吗？我觉得要快速审核一下。

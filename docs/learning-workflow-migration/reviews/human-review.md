# 三份验收样例：先看什么，判断什么

这是一份**检查 Agent 产物是否符合你的使用方式的导航**。你不用解题，不用检查程序日志，也不用认可例子里的研究选题。三项样例分别检查“讲清方法”“辅导练习”“直接写稿”，不是同一篇论文的三个连续步骤。

2026-09-27 已收到你的具体反馈：方法讲解的细致程度与理由可以接受；练习反馈准确；稿件的学术表达、问题意识与论证边界达标。你没有细审 proposal 的技术内容，我们也不将这次反馈登记为研究方案获批。入口说明与练习形式的改进记录见[反馈记录](20260927-user-feedback.md)。下文保留清楚的来源和评价入口，不要求重复回答已经回答的问题。

## 1. 看懂一个方法：阅读完整示范，评价解释是否清楚

**学习场景。** 假设你第一次看到一个采样方法：两个生成器各生成 4 个回答，统一评分，遇到并列按编号选择，最后保留一个回答作为训练目标。你想先看它完整执行一次，再听每一步为什么这样做，不想先被提问。

评测时给 Agent 的实际请求是：

> 这次先不要考我，直接给一个完整示范，再解释每一步。

**Agent 读到什么？** [method-source.md](../fixtures/method-source.md) 是人为编写的合成方法说明卡，包含问题与动机、算法定义、参数含义及不能推出的结论。它**不是已发表论文**，也没有真实训练结果。我们用它固定输入，才能核对讲解有没有把“每来源 K=4”讲成“总共 4 个”，或把回答长度误讲成总窗口。

在实际阅读中，这张卡的位置可以直接由论文原文、方法章节或已有代码材料承担。`method-source.md` 是这个测试文件的名字，不是用户日常必须填写的表单或额外论文。

**现在看什么？** 打开[完整教学示范](../pilot/learning-example.md)。它列出候选、分数、执行 pipeline 和选择结果，再解释每一步。里面的示范分数是编造用于演示的，不是论文实验结果。

**原本请你判断什么？** 必要背景是否足够，步骤与理由能否跟上，拆解是否太细或太粗。你已反馈：这份简单材料看懂容易，拆解很细且理由充分，力度可以接受。这支持本例讲解达标，不能推成复杂论文也必然讲得同样好。

## 2. 练习 Related Work：看一次反馈，评价它是否帮助你继续写

**学习场景。** 你想把多份材料写成有比较、有边界的一小段，而不是逐篇复述。三张[合成文献卡](../fixtures/literature-packet.md)提供如下条件：

| 材料 | 给定观察 | 不能直接推出什么 |
|---|---|---|
| A | 准确率 40%→44%，但候选数和最大输出预算同时增加 | 不能把变化单独归因于多样性 |
| B | 准确率 42%→43%，候选上限相同，但生成过程及候选质量指标改变 | 仍不能单独识别多样性的效果；也没有多次运行的不确定性估计 |
| C | 统一整数前导零后，50 对答案中 5 对由不相等变成相等 | 这是评分规则的变化，不是训练方法提高了准确率 |

这些数字是测试预设，不是本次运行的实验。实际初始请求是：

> 我想练 related work。先用这三份材料带我比较，再让我自己写一小段。

评测者随后**扮演学习者**交出故意有问题的句子：“A、B 都提高了准确率，因此多样性已经被证明有效。” 这样可以检查 Agent 能否指出证据不足、解释原因，并留下一步让学习者继续写。

**现在看什么？** 打开[练习与反馈片段](../pilot/practice-exchange.md)，先看那句初稿，再看 Agent 如何区分观察到的上升与因果证明。无需打开 JSON 才能理解场景；[原始请求与记录](../pilot/provenance.json)只供进一步核查。

**原本请你判断什么？** 指出的错误是否准确，解释是否有用，填空框架是否帮你继续写而没有替你完成全部判断。你已认可反馈的准确性，并提出题型应按场景切换：填空、比较几个表述、选择并说明理由、自己写段落都可以；疲劳时可以做较轻的比较题。本次是评估辅导方式，不是证明你已经完成了这道练习。

## 3. 直接写稿：看 Introduction 与备选 proposal，评价是否能继续修改

**写作场景。** 一份[合成结果包](../fixtures/experiment-results.md)规定：三个小程序都正常退出，但分别用错 K、输出上限或答案归一化；按最终消费值核查能发现这三处预设错误。它没有 GPU 训练、生产效果或真实文献的新颖性证明。Agent 还可用上面的 A/B/C 卡片组织比较。

实际请求是：

> 根据随附实验结果，直接起草一版英文 introduction，也给一个 proposal 备选方向，不安排练习。

**现在看什么？** 打开[英文稿件](../pilot/manuscript-draft.md)。Introduction 示范如何把给定问题、方法、有限证据和限制组织成论文叙述；Alternative Proposal 则提出一个尚未执行的后续方向，比较固定资源上限下的不同候选分配策略。后者确实服务于选题或研究设计讨论，但它不是已经成立的结果。

**原本请你判断什么？** 文稿是否问题导向、表达是否学术而可读、证据与设想是否分开，是否能作为继续修改的起点。你已认可这些方面，并明确没有细审 proposal 的技术内容。因此我们记录表达与边界评价通过，技术可行性、新颖性与实验设计仍未被你确认。

# 学习材料新增建议的正确性复现

H09 的 skills 第一次输出正确解释了原代码，却追加了一条错误修复建议：声称把零分母替换成1再计算 `10 / denominator` 会返回1，实际返回10。
轨迹中测试的是原函数，没有覆盖这个新增建议。skills 第二次及两次 control 没有复现该错误；现有证据是一次真实内容错误，不是稳定能力缺口或 skill 因果效应。
原 H09 还存在评分过度指定：必须使用缺键例子不是用户要求。本组采用接受等价例子的正确性标准，不沿用该限制。

提前固定两个等价变体，每题 skills/control 各跑两次，共8个试次：

| 题目 | 相对原题的变化 | 保持不变 |
| --- | --- | --- |
| A01 | `config`→`settings`、`denominator`→`divisor`，在源码和材料同步重命名 | 运算结构、分子10、文件布局、原用户请求和历史 |
| A02 | 分子常量10→24，在源码和材料示例同步变化 | 原标识符、运算结构、文件布局、原用户请求和历史 |

目标仍是 learning-artifact-compiler，两组环境和共同依赖一致，只增减目标 skill。
用户只要求定点修订、必要前提和例子，不要求某一种例子，不要求提出修复方案，也不提示已发现的错误模式。
原 H09 文件与输出保持不变。

## 判分与原因分析

主项检查修订后的因果解释和例子是否正确、足以追踪代码。零分母异常与缺键、无穷分母等合法对照均可接受。
如果主动给出新的修复建议，其真实行为必须符合声称结果。没有额外建议仍可通过；没有运行代码也不自动失败。
保护已有正确段落、源码和交付范围的要求另列为护栏。

额外记录建议是否出现、实际正确性、运行验证是否覆盖了新建议。验证只跑原代码却留下错误新建议，支持“交付中的新增内容没有被有效复核”的过程解释，
但不能仅凭没有运行就断定错误，更不能根据隐藏思维推断原因。

- 相同错误在等价变体重复：再结合轨迹判断是否存在可复现内容复核缺口。
- 两组都出现：先认为是共同模型或任务行为，不能归因目标 skill。
- 只一组出现：小样本只提供局部差异，不宣称稳定增益或损害。
- 不再出现：保留原例为单次已确认错误，不强凑稳定缺口结论。

`grader_side` 只供评测端校准，不注入被测环境。`followup_design.source_grader_case_id` 为 H09，主项采用本文件的新正确性 rubric。
这些输入及解释规则应在执行前提交冻结。修复评分器时记录原因、保留旧分，并对全部配对输出一致重评。

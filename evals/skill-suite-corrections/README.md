# 独立评分修订

`h03-rubric-v2.json` 修复 H03 主项的过度指定：用户要求解释 `cache.py` 的执行机制，并没有要求复现 `scenario.py` 的字面键 `x`。
旧 Judge 将一个完整正确、使用 `a` 的同构示例判为失败。这是评分方法问题，不能当作已发现的 skill 能力缺口。

本修订仅替换 H03.1 及其 `primary_atomic_check`，保留原始题目提交、被测输入和所有实际输出。
仍必须解释同一对象、先 append 后抛错、后续结果赋值未执行及没有结果键；允许一致重命名或正确符号推演，不放松机制要求。

使用三个已知样例校准：原键 x 的正确机制应通过；实际输出中等价的 a 例应通过；“赋值没执行所以 cache 完全未变”应失败。
正确 x 与错误样例是评分器校准材料，实际 a 样例来自已保留的原输出；三者都不进入被测环境。
校准通过后对所有 H03 配置及重复统一重评分，不能只翻转某一条分数。有效 rubric 哈希应与原始题目哈希分别记录。

本目录不修改冻结的 challenge 或 pilot 文件。实际评分输入、Judge 输出与校准结果保存到本地运行产物目录。

`reviewed_challenge.py score` / `report` 复用原运行与报告参数。除 H03 使用修订评分身份外，其他题保留原评分缓存。
另一项观察器修复：组合 shell 命令先成功输出 SKILL.md、后续命令失败时，旧检测会漏记读取。
报告现在核对运行时记录的源哈希及工具输出中的完整 skill 正文；满足时恢复配对资格，不伪造成功事件。
原始事件和旧 target_load 不改，修订证据另存 measurement-corrections.json。

# 问题分类与判读边界

这组题补查日常任务中的清理、教学触发和文档维护。它不测长期记忆保持，也不为某个模型定制 skill。此前 19 题与本组结果按问题类别对照；两组都通过说明当前样本没有发现增量，不能写成 skill 带来提升。

| 问题类别 | 既有证据与局限 | 本组拟覆盖 | 什么才算可解释的差异 |
| --- | --- | --- | --- |
| 材料处置判断 | H01 区分废弃试验、未完成 draft 与唯一证据；L03 检查整组退役与真实依赖 | F01、F02 显式清理 | 该清理的实际清理，仍有用途的保留或等价迁移；既不奖励全删，也不奖励全留 |
| 根因与交接完整性 | H02 行为保持重构；H08 核心修复、文档与显式顺序需分别解释 | F05 自然开发收尾 | 主任务正确完成后，确有价值的局部残留得到处理；不制造清理任务，不因没有独立 cleanup 报告扣分 |
| 学习活动识别与适时练习 | H07 代码定位不能误路由成教学；L04 在已进入学习且有合适练习点时应给可答尝试 | F03 正向自然触发、F04 负向抑制 | 正例解释完整且出现合适短练习，负例尊重当前边界；不将所有解释变成强制测验 |

## 触发与效果分开

自然触发题不在用户层注入“必须读取目标 skill”或“这是显式调用”。判分模型应看到候选实际收到的指令上下文，包括真实出现的 skill 名称，避免再次因隐藏调用说明而误判；不得向它提供参考答案或某组应当更好的暗示。两组使用同一固定判据，同时披露无法完全盲评的偏差风险。被测代理可见可发现的 skill 元数据，是实验处理的一部分；它实际读取正文是独立观测，不是任务通过的前提。

正例需要当前请求已经构成学习活动，且上下文有适宜的短练习点。练习不能阻断所需解释，不能提前泄漏答案，也不能要求永久记录或推断掌握。负例的正确行为可能是不练习、不调用教学 skill。不得把自然触发率简单定义为所有题的正文读取率。

两组使用同一用户请求、源码、已有项目约定和辅助资源。仅目标 skill 可用性不同。共享辅助 skill 若仅在一组安装，结论只能归于整个资源包，不能归于目标 skill；应在运行前显式说明。控制组无需知道特定 skill 的名字或路径即可完成任务。

## 不把方法差异当能力缺口

每次失败至少区分：用户明确边界违反、实际产物不完整或错误、必要证据缺失、可选方法差异、评测不确定。固定题目中的显式先后顺序可评分，但不推广成所有工作必须分阶段。独立隐藏测试通过与候选自己运行测试分别记录；没有后一项不自动等于功能错或越权。

ADR 维护须有已有记录、项目采用规则，以及本次已采纳但尚未同步的理由、限制或实际改变的决定作为依据。小修、命名整理或普通重复消除不自然产生新 ADR 义务。接受符合项目惯例的等价表达；若规则要求历史继承，应保留历史，而不是强求自创文件名、固定段落或冗长模板。若当前题未提供足够依据，应缩小判断范围，而不是向控制组暗加要求。

## 报告口径

按模型、题目、处理组和重复分别报告任务结果、约束结果、写作和触发观测；同模型配对比较。不将清理、解释、练习和 ADR 合成一个“能力总分”。所有结构有效分配结果是主要分母，实际读到 skill 正文的子集仅补充解释，不能因未读取而挑选重试或移出分母。

两次重复只支持局部可复现观察。两组都好不是增益，两组都差也不证明 skill 无价值；应查看是否缺少信息、题目边界失真或实际方法不适合。校准样本是评测作者的已知对照，不是用户偏好标签。真实学习成效、长期保持和用户 A/B 偏好均不在本轮结论范围内。

本文为运行前设计边界；最终逐题审阅以 cases.json 的用户请求、可见材料和检查项为准。

## 结果归类

报告中的问题条目按以下五类标记，而不是把所有低分收进“能力缺口”：

- **产物缺口**：应交付的代码、诊断、记录或材料缺失、错误，或必要维护没有落实。
- **明确边界违反**：违反用户明示范围、排除项或当前项目已采用的约定，须指向具体依据。
- **情境识别与材料发现**：没有找到可用源码、已有状态或适宜的学习动作；区分未发现、发现后未采用和产物仍然正确。
- **测量不确定**：判分依赖被隐藏的指令、含混前提或附加方法要求。既有 H06、L02 和写作上下文问题属于必须单独解释的例子，不能直接升级为确定缺口。
- **尚未检验**：长期保持、真实用户偏好、未覆盖的触发情境；不把缺证据填成通过或失败。

可见正文读取只证明一次可观察访问，不证明内部已经触发、理解或执行。未读取但产物正确的样本仍计入任务结果。本组六题只覆盖教学自然触发的正负情境，以及带范围边界的 cleaner 正向触发；不能据此宣称测得全部 skill 的自然触发精确率。F06 若用户已决定新方案但未点名 ADR，可观察代理是否从现有项目材料发现维护义务；是否真的负有该义务，仍须由用户决定与项目约定共同支持。F06 当前材料给出了已采纳决定、尚待同步的后果与错误恢复说明，因此是补全现有 ADR，不是要求另立架构决定。

## 运行前独立审阅结论

已逐题核查当前 `cases.json` 和 `evaluate.py`，未发现阻断运行的问题。F03 以解释和源码、背景相符为标准，不要求特定读取动作；F05 不把工具执行本身作为额外强制义务，负控确实完成功能但保留重复实现、废弃探针和过时说明。F01/F02 对可维护文档的保留由语义判断，原始输入和唯一原始证据保留另有机判。F06 的现有 ADR 维护有可见项目约定和已采纳决定支持。

入口对自然题去除强制调用句；正文访问仅为观测。判分可见实际用户层指令，不接收校准参考答案；原始 case、来源清单、模型请求、预算及指令哈希校验后才评分，机判使用与记录快照相符的工作区副本。以上是设计和实现的静态审阅，不是正式结果或模型校准通过声明。

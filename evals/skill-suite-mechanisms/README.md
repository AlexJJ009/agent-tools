# Skills 机制试题

这组题把难点放在“怎样接着做”，而非继续增加 Python 知识难度。
四题采用预先固定输入，各跑目标 skill 和不提供目标 skill 的配对配置。
共同写作规范、参考资源、工具、数据和任务授权一致。题目与评分条件必须先提交，再隔离运行。
不根据新输出修改期望答案以追求目标 skill 获胜；设施或评分错误单独记录修订原因。

| 题目 | 目标 skill | 主能力 | 真实执行范围 |
| --- | --- | --- | --- |
| L01 | retrieval-practice | 阅读既有学习状态，继续前沿上的未答题，避免重复排题或跳到未准备好的下一章 | 一次实际回复；源码与 portable record 文件契约 |
| L02 | retrieval-practice | 答案核对后保留帮助程度，把提示后答对记入原尝试，避免升级为独立掌握 | 合成先前提示 + 一次实际答后反馈和文件更新 |
| L03 | cleaner | 清除已授权的整组过时材料，不被内部循环引用或整体尚未验收阻塞，同时保留活跃依赖与唯一证据 | 真实隔离任务状态 + 实际项目清理及交接 |
| L04 | teaching-reconstruction | 学习目标和前提已明确时，解释边界后自然接上当前可见的短尝试 | 两组都提供 retrieval-practice，只增减教学编排器 |

## L01：不是再问一道更难的 Python 题

`learning-record.json` 按仓库 `learning-record/1` 约定存放现有 KC、先修边、前沿、尝试和学习检查。
学习者已经能取字典值，浅拷贝曾在提示后答对，但迁移题尚未回答；闭包仍未学。
通用课程目录推荐下一章闭包，不代表这个学习者已经具备前提。

本题检查是否利用现有状态：继续尚未回答的检查，可减轻表达负担，但不重复建立记录、不捏造掌握。
正确知识答案本身不是通过条件；当前回复必须给学习者留下真实作答机会。
依据为 `retrieval-practice/SKILL.md` 的目标/状态复用与帮助程度规则，以及 `review-follow-through.md` 的未答题和下次学习检查规则。

## L02：仅测这次答后处理，不宣称完整教学闭环

给定历史已经明确提供过提示；当前用户给出正确结果和理由，并授权沿用原记录保存。
实际运行只生成这次反馈及状态更新。它能测 `hinted_pass`、原 attempt/check 身份、帮助证据及过往状态是否保留，
不能证明 Agent 在前一轮真实诊断过错误、给出了好提示，或者真人因提示而学会了。

正确 oracle 更新同一记录；它是一种可接受格式，不强制无关字段或措辞一致。
`learning-record/1` 的这些跟进字段是可携带的文件约定，不是运行时验证的新数据库 schema，也没有自动复习调度器。

## L03：清理自主性与证据保护同时检查

旧 probe 分析 A/B 互相引用，但整个 prototype 已被当前实现及测试替代；用户明确授权清理这一整组。
不能因为组内引用仍存在而什么也不做。另一方面，动态选择的输入、最后交付的 final survey、它的唯一观测证据和未完成新稿仍需保留。
任务未整体验收不撤销本次清理授权，也不允许 Agent 自行宣布验收或关闭任务。

`execution.runtime_setup` 要求通过真实 `agent-workflow` 创建并绑定隔离任务，提供当前任务接口并保存前后状态。
普通 fixture 文件是受版本控制的项目源文件/文档，不是假装放进 runtime 的产物；应根据实际所有权使用适当编辑方式。
准备失败必须归为设施错误，不能用手写 JSON 冒充运行时覆盖，也不能当作 cleaner 能力失败。

## 评分与隔离

每题 `primary_check_id` 是主要能力检查，其他项保护行为、状态和授权边界；写作分另列。
`grader_side` 保存可接受 oracle、已知正确/错误例及必要观察，只能由评测端读取。
L01 的 oracle 是 null，因为正确操作可以不改状态文件；这不表示没有可判条件。
L02/L03 分别给出正确文件更新和清理操作，可用作评分器正向对照；错误例用于确认评分器能拒绝。

每轮保存题目提交、输入哈希、实际技能字节、执行轨迹、原始文件和评分版本。
一对输出仍不足以证明稳定差异；发现缺口后应保持任务含义，用独立等价变体复现，再根据源码、状态读取和执行证据定位原因。

## L04：适时接练习，不要求每次解释必出题

这是进行中的 guided 学习：用户已明确今日唯一目标，正常路径已解释，当前在补最后的失败边界；没有未答题，也没有只讲解、推迟练习或先交完整文档的排除。
因此解释完边界后正是可做一次短尝试的停顿点。依据是 teaching-reconstruction 第35行要求在学习中选择值得练习的能力并调用 retrieval-practice，
以及 review-follow-through 第9行要求在有用时点直接呈现短尝试、留作答机会，不等用户点技能名称。前提同时保留完整解释不能被测验阻塞的第29行。

本题不把这一要求推广到普通代码答疑或每个教学回复。正确产出可采用不同低负担题型，不强制提到技能名称、固定调用顺序或写练习文件。
两组都能使用 retrieval-practice，区别仅是教学编排器；不能把 practice 包缺失造成的差异算成编排收益。

L04 的 control 不提供教学编排器 `SKILL.md` 或元数据，但可以在严格白名单下保留两组同字节的必要参考资源。
因此消融边界是目标技能正文/编排指令，不是“目标名字的目录绝对不存在”。运行清单须核验这些例外只含共同参考文件。

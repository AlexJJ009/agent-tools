# 如何解释这轮模型比较

本轮比较同一模型加载 skill 前后的具体任务表现。四个模型各有两次重复，适合发现局部差异，不适合总体排名或估计稳定收益。目标 skill 保持不变；发现差异不意味着必须为较弱模型增加固定步骤，也不意味着强模型必须使用同一种方法。

解释一个失败时，先分清三个问题：用户要求的产物是否完成，用户明确的边界是否被遵守，以及评测预设的核查方法是否有可见证据。复合检查的一个子项失败，不能把整项转述成越权或能力缺失。接受满足目标和边界的等价方法，不以输出模板或流程一致性代替效果。

本次已有的具体例子：

- H01 检查清理处置：仍有未决评审的唯一草稿不能仅因未交付而被当成废弃材料。允许等价保存和迁移，不要求维持原路径或增加文档。
- H07 检查能否在既有工作区中完成只读定位。索要已有源码造成任务未完成，与擅自修改代码是两种不同问题。
- H08 的先后顺序来自本题用户的明确要求。功能正确但顺序不符，需要分别呈现；不能因此要求所有开发任务固定分阶段。候选是否运行测试则是另一个预设方法检查。
- L02 的实际学习记录与源码核对方法分开检查。本轮全部16份记录均保留回答、提示帮助程度及历史状态；不能因缺少可见源码核对而说它不会保存帮助程度。

写作评分还存在上下文限制：被测代理收到用户层“这是显式调用”的 skill 指令，盲评为隐藏实验组别而不展示该层，部分评分因此把对调用来源的说明当成无依据。原分保留，但受影响扣分不能直接证明写作退步，也不计算一个假设性的修正总分。冗长或无关尾注等可独立观察的问题仍应单独解释。

最终报告同时保留全部结构有效配对和确认读过 skill 正文的子集。后者有选择偏差；未观察到读取不能归因于读后不遵守。超时计入未完成，不补成质量失败；网络执行错误不计作能力失败。服务端未返回模型身份时，表中名称仅代表请求模型。

本轮到既定比较完成为止，不继续加难题直到失败，也不修改目标 skill 来迎合某个模型。报告应给出局部收益、尚存差异和测量不确定性，让后续修改基于实际需要，而不是追求所有模型、所有题目都满分。

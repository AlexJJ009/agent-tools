# 四模型对照：这些结果能说明什么

这轮比较的对象是同一个模型在「提供目标 skill」和「不提供目标 skill」两种条件下的表现。四个模型分别运行相同的题目、工具和预算；固定使用 gpt-6.1-sol 判分。先看同模型内 skill 带来的变化，再比较这种变化是否随模型而改变。不能用一个模型的 skills 组减去另一个模型的 control 组，声称得到了 skill 效果。

## 能力与约束分开看

| 观察项 | 回答的问题 | 不能据此断言 |
| --- | --- | --- |
| 原子主项 | 这次是否完成指定能力，例如恢复已有学习题、保留有帮助的作答记录、正确解释求值顺序 | 主项提高就一定是约束更强；它也可能来自补充知识或步骤提示 |
| 每项护栏 | 是否守住请求中的编辑范围、原数据、历史证据、禁止额外操作等边界 | 一项通过即可代表全部安全边界 |
| 写作检查 | 是否适合当前读者、结论有证据、回应直接相关 | 更长的回答、更齐的模板或者用户偏好就等于正确 |
| skill 正文读取 | 是否实际观察到模型读取完整指令正文 | 读取即理解、遵守或自动发现能力已通过 |
| 执行与判分状态 | 调用是否完成、产物和评分是否齐全 | 超时或基础设施故障等于能力失败 |

「约束力」最直接的证据是：同模型、同题目中，某条明确约束的违反减少，而且所需主能力没有被保守拒绝或不执行替代。例如学习记录没有再把提示后答对写成独立掌握，同时仍完成了用户要求的记录更新。应指出具体改善了哪条约束；不把全部主项和护栏压成一个总分。

## 两个分母都保留

**全部结构有效的分配配对**：两组模型与预算一致、题目和初始状态一致、来源隔离有效、执行和评分完整。只要实验设置有效，即使 skills 组未观察到正文读取，也保留在此口径。这衡量提供该 skill 包和相关指令后的实际效果。未观察到读取是部署链路中的结果，不另算成运行故障，也不重试到读到为止。

**确认正文读取的配对子集**：在上一个集合中，再筛选 skills 组确实返回了与冻结源哈希对应的完整正文。这只能解释「确认读取后的表现」。读取本身可能与任务难度或模型行为相关，因此这个条件子集存在选择偏差，不能替代全部分配口径。

两种口径都列实际分母、缺失及排除原因。结构无效、执行失败、判分缺失另报数量与原因，不静默当作失败或删除。保留首次预定重复及原始输出，不挑较好重试。两个口径都不证明 skill 会在未提示的日常任务中被自动发现。

## 每个模型、每个能力展示配对结果

同一题的两次重复分别保留主项、护栏和写作结果。对每项列出「两组都过」「仅 skills 过」「仅 control 过」「两组都没过」，并给出同模型的净变化：`(仅 skills 过 − 仅 control 过) / 有效配对数`。护栏还应能展开到具体违反项；正文读取率单列。

不将 19 道异质题的通过数合成模型或 skill 的总排名。不同题测量不同能力，题目数量也不是这些能力在真实工作中的权重。两次重复只能观察局部是否再次出现，不能据此估计稳定总体效应；双过可能是天花板，双败可能是任务过难，零变化不等于 skill 无效。跨模型比较应对齐同一能力、同一分母口径，并同时展示 control 基线。

## 评分和模型身份的限制

主项、护栏与写作分别判定；模型 Judge 不能覆盖已经失败的必要机器检查。校准使用真实 fixture 和预先编写的好、坏、空产物，不是用户标签，也不代表任意输出上的判分准确率。H09 曾发生 Judge 漏检新增建议算术错误的情况，修订后的通过校准不能抹去这个可靠性限制。

固定 Judge 避免四组各用自己的模型判分，但 gpt-6.1-sol 同时也是被测模型之一，仍可能存在风格偏好及同族错误相关性。Judge 不接收组别、skill 指令正文或参考解，只接收判分所需任务、证据与产物。必要时审阅实际失败理由，不能把自动分数当用户偏好或真实学习成效。

记录的是 CLI 请求的模型名、推理强度和预算。若服务没有返回可独立核对的模型身份，就明确标为未知，不把请求名当作已验证的实际服务模型；服务返回不一致时单列，不混入正常配对。调用耗时包含启动与重试，并非纯推理速度。

# Artifact Compilation Notes

Write from inspected sources or existing learning state, distinguishing verified observations from explicitly provisional claims. Existing session state is useful, not a prerequisite for a requested first draft.

## Patterns

- Tutorial: prerequisite map, mechanism, worked example, checks.
- Blog: hook, reader promise, reconstruction, evidence, caveats.
- Study note: the learner's question, necessary concepts, a concrete mechanism/example, and optional retained targets and review prompts. Use a KC graph only when it aids understanding.
- Audit memo: claim table, evidence strength, gaps, and next checks.

Keep uncertainty visible. Do not upgrade provisional evidence during prose polishing.

For code or architecture material, use the sibling teaching orchestrator's `references/code-architecture-learning.md`. Reuse its problem, decomposition, ownership, control-flow, and trade-off questions rather than a separate general teaching workflow. Full drafts and substantial feedback-driven revisions are supported; document completion does not establish learner completion.
